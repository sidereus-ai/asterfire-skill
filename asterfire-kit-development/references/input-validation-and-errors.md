# 输入校验与用户可见错误

新建、适配、修改和审查 Kit 时，检查本次功能涉及的输入契约、入口校验和失败报告。已有 Kit 优先复用原解析器与异常处理，修复正常入口可触发的问题。下表用于选取适用场景，具体格式、支持范围和阈值以当前工具及部署版本为准。

## 校验放置与契约

- 表单负责提示类型、必填项及允许值，执行入口在加载权重、申请外部计算或启动核心子进程前验证实际收到的数据。API、Workflow 和旧请求也必须经过入口校验。
- 可选数组未提供、为 null 或为空时，按契约处理其缺省含义。仅在存在的记录内检查条件必填字段。核对平台生成的 config_schema，尤其是隐藏旧字段、批量任务和逐实体文件。废弃字段的清理与旧请求兼容分开实现。
- 同一数据有新版与旧版字段、直接上传与 ZIP 内路径、文本与文件等多种来源时，明确优先级或互斥关系。防止默认值或旧字段覆盖用户明确提供的序列、MSA、链号、约束和文件。
- resAlloc 只读取资源估算所需的信息。完整内容校验在 call 的预检阶段生成可见报告。估算本身遇到错误时，使用已核实的平台结构化预检/失败机制；如平台支持 CPU 检查任务，可在该分支生成报告并结束。不得用未经校验的资源方案启动模型。
- resAlloc 与 call 共用必要的解析和计数逻辑。会影响资源的输入发生改变时，核对内容指纹、参数及所选方案并要求重新申请。附件的本地投递路径变化可按平台契约归一化。

## 常见问题与适用检查

| 输入或环节 | 检查内容 | 错误需定位到 |
| --- | --- | --- |
| 附件、路径和目录 | 缺参数、空字符串、缺文件、文件/目录类型混用、单文件收到多项、当前任务可读性、URL/本地路径类型、未解析变量与占位符 | 参数名、附件名、收到的类型及当前入口要求 |
| ZIP 与依赖文件 | ZIP 真实可读性、路径安全、所需成员、相对依赖、同名文件的目录与上传标识；容量限制采用该入口真实上限 | 归档名、缺失成员或依赖名、超限项及允许范围 |
| PDB、mmCIF、拓扑和轨迹 | 格式及模型完整性、有限坐标、链和残基是否存在、主链完整性、重复原子与 altLoc、插入码、auth/label 链号、坐标拓扑数量及原子身份/顺序 | 模型、链、残基、原子或首个异常位置；实际与期望数量 |
| FASTA、序列和 A3M | 标题、非空记录、合法字母、唯一 ID、链命名、序列与结构逐位对应；按当前解析器的插入和缺口约定检查 MSA，核对查询序列及逐实体归属 | 记录编号、标题行或字段路径、字符/位置、对齐长度及查询链 |
| 小分子与格式转换 | SMILES 文本/文件区分、语法、价态、芳香性、工具要求的氢与片段限制、SDF 逐记录有效性、立体构型保留能力 | 分子记录 ID、原子或片段、转换丢失的信息 |
| 材料与量化 | 晶格与坐标块、原子数、非零晶胞体积、坐标单位/坐标系、网格、赝势及前序密度/续算文件、求解器/模式/自旋组合、读取器支持的格式名 | 文件段、参数名、缺失依赖、单位或不支持的参数组合 |
| CSV、JSON 与列表 | 编码、语法、列数和必需列、数值与对象类型、整数索引、嵌套必填项、记录 ID 唯一性与前导零、按键关联、缺省/null/0/false | 行列、记录 ID、列表索引或完整嵌套路径 |
| 工作流交接与重跑 | 上游输出 key 与实际产物、变量解析、工作目录归属、同名附件标识、替换附件后的哈希与缓存版本、输出目录冲突、复制源目标相同 | 节点/端口、附件版本与缺少的产物；重跑需要修正的绑定 |

空文件、全缺口或空列表能否接受由工具契约决定。单位转换、结构重编号、缺口填补、丢弃坏记录、自动补氢、改电荷、截断序列等操作会改变解释或科学条件，须遵循用户选择与工具明确支持的规则，并在报告中说明发生的转换。普通语法合法之后，还要校验相关输入之间的对应关系。

## 报告中的具体错误

失败时在当前任务目录生成 report.md，并通过已声明的 report 输出返回。报告至少包含运行失败的阶段、具体原因、错误位置和可执行的修正办法。可获得实际值和期望值时同时给出。任务和批次标识只使用本次运行已知的信息。

面向用户的例子

> 输入校验失败。A 链的 A3M 第 2 条记录（标题在文件第 4 行）去掉插入位点后有 18 个对齐列，靶点需要 20 列。请检查该记录的对齐长度并重新上传。

> 输入校验失败。residue_table 第 3 行缺少 resi 列的整数值，请补全后重新提交。

> 输入文件不完整。system.top 引用了 toy.itp，但附件中未找到该文件。请连同依赖文件一起上传，并保留相对目录。

- 已知输入错误用领域语言解释。外部程序失败时保留退出码，并从可核实的诊断中提取主要原因。无法归因时明确说明停止阶段和已知事实，避免把环境、传输、OOM 或未收敛一律归为输入错误。
- 详细 traceback、stdout/stderr 和工程诊断写入 run.log；报告呈现必要的错误摘要及日志入口。对报错文本和参数做脱敏，报告与日志均不得泄露凭据。
- 输入预检失败时返回 report、run_log 等本次已生成的文件及 success=false。仅返回确实生成且属于本次运行的产物。发生异常、子进程失败或关键产物缺失时，不得沿用旧目录文件认定成功。
- 部分成功时列出每项的记录 ID、状态和失败原因，按工具原有整批/逐项处理语义汇总。批处理中坏记录不得造成后续结果 ID 错位。
- 在目标平台核对报告回流与失败状态。返回 success=false 后，需确认平台及 Workflow 能识别业务失败；若平台契约要求抛异常，先使用其支持的报告回传机制，再按该契约标记失败。控制台有日志或本地写出 report.md 不足以证明用户能看到。
- 纯输入失败可用简短报告，直接说明原因与修正办法。结果图表和结构预览适用于本次实际产生的有效结果。

## 开发与修改时的回归

1. 从本次支持的输入选择一份正常对照，再只改变一个条件构造代表性异常。优先覆盖曾发生的错误及本次改动影响的边界，测试矩阵以实际入口为准。
2. 通过真实 call/API/Workflow 入口检查结果，核对用户可见报告的字段/文件/行号和修正办法、success 与平台状态、日志文件和产物归属。输入错误应在核心计算前结束。
3. 相关功能涉及多来源、同名附件、批量、重跑或缓存时，验证绑定和版本一致性。涉及容量限制时检查 N−1、N、N+1，采用真实限制，不把演示值固化为全局规则。
4. 保留每项已执行检查的输入差异、运行标识、报告位置与结论。只做本地验证时据实列出平台契约及回流未验证项，并写入六项验收的相应证据栏。

本规范归纳自输入回归样例的格式、语义和文件交接场景。历史报错样例用于选择回归条件，适用规则仍须由当前工具契约确认。
